## Context

At Quadion Tech I work for one of Argentina's leading health insurers, on the
migration of its member portal: reimbursements, authorizations, billing,
disability and many more requests, used by members and healthcare providers.
Several development teams work in parallel on the same platform.

## The architecture

The migration started with **microfrontends using Module Federation**: an app
shell handled authentication, layout and navigation, and each request was an
independent microfrontend. Later, by client decision, we consolidated the
platform into a **modular monolith**, where each request is still an independent
module loaded on demand. I worked with both architectures.

## Challenge 1: everything has to look and behave the same

With several teams building in parallel, each one risked creating its own
buttons, forms and patterns. To prevent that we created a **shared component
library** that, since this was a migration, had to be rebuilt from scratch. I
built many of its components in **Storybook**, working closely with the
design team from **Figma** files:

- **Steppers and breadcrumbs**, present in every request.
- **File upload**, which uploads documents in two steps using signed cloud URLs.
- **Centralized analytics functions**, so every request tracks its events the
  same way.

Every component follows the same path: design in Figma, development and
documentation in Storybook, unit and end-to-end tests in the pipeline, and only
then does it reach the requests.

## Challenge 2: resilience

A platform with this many requests depends on many services, and a single failure
can't take everything down. We built a **contingency system with Firebase
Remote Config**: the app polls the configuration every minute and, depending on
what it finds, **turns off a single request**, **shows a maintenance notice with
date and time** or **puts the whole platform in maintenance**. All without
deploying.

## Quality and deployment

Unit tests (first with Jest, later migrated to Vitest), end-to-end tests with
Playwright and GitLab pipelines with security scanning that deploy to Kubernetes.
The same build also runs in every environment, because the app reads its
configuration at startup.

## Results

- **Consistency:** members and providers see the same components in every
  request.
- **Resilience:** when something fails, one request goes down, not the platform,
  and with no deploys.
- **Team velocity:** an improvement to a component reaches every team at once.
